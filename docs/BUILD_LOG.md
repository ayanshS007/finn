- **Migration NOT applied to Supabase.** `psql "$SUPABASE_DB_URL"` fails from this sandbox with `could not translate host name "db.<project-ref>.supabase.co" to address: No address associated with hostname` (the direct DB host has no A record here and only HTTPS is allowed out; a raw TCP connect to a pooler timed out). Run `make migrate` from a machine that can reach it (use the pooler URL if your network is IPv4-only). Instead I applied it twice to a local Postgres 16 with `anon`/`authenticated` roles created, confirmed the 12 tables, anon read-only (insert/update/delete denied on all 12, select denied on cache, llm_calls, push_subscriptions, swipes), and that Fact rows from `results_facts` insert and upsert (24 rows after two passes, not 48).
- What the integrated-filing XBRL actually holds (S1's note was right about the endpoint, but each file is thinner than expected): one basis per file, the quarter just reported (context `OneD`), the year to date (H1/9M/FY, `FourD`) and a balance sheet; the previous quarter and the same quarter last year are NOT in it. `results_facts` therefore downloads up to three filings (current, one quarter back, four quarters back; INFY has 14 filings from Mar 2025). Money is plain rupees (`unitRef INR`), `decimals` is only precision (-7 = to the crore, banks -5 = to the lakh). Basis comes from the `NatureOfReportStandaloneConsolidated` fact and is checked against NSE's row; a mismatch raises.
- Source order per period, all on one basis (consolidated if the current quarter has it): XBRL -> screener quarterly table -> legacy `results-comparision` (only up to Dec 2024, and only for standalone companies). A blocked or reshaped source raises; only a period with no row falls through. A period no source has is logged and omitted.
- Cross-check, INFY FY27Q2, XBRL vs screener consolidated: revenue 49,244, EBITDA 11,689, other income 848, finance costs 115, D&A 1,359, PBT 11,063, PAT 7,838 - every line identical (0.000% gap). Screener's "Operating Profit" equals our derived EBITDA, and screener's Net Profit equals XBRL `ProfitLossForPeriod`.
- Decisions:
  - `pat` = `ProfitLossForPeriod` (profit for the period incl. non-controlling interest, so `pbt - tax = pat`). INFY's attributable-to-owners profit is 7,823 (0.19% lower); not stored.
  - Banks: `revenue` = XBRL `Income` (interest earned + other income), `ppop` = reported `OperatingProfitBeforeProvisionAndContingencies`, `nii` = interest earned - interest expended (derived, formula stored); no `finance_costs`/`d_and_a`/`ebitda`. NBFCs (Ind AS file with `InterestEarned`): `nii` = interest earned - finance costs, `ppop` = PBT before exceptional + impairment, both derived; they keep revenue/finance_costs/d_and_a but get no `ebitda`. Lender detection is by content, not URL.
  - EBITDA = pbt + finance_costs + d_and_a - other_income exactly as specified, so exceptional items stay in it (INFY, GRAVITA have none this quarter).
  - Facts carry as `quote` the XBRL element as written in the file (`in-capmkt:RevenueFromOperations contextRef="OneD" ... >492440000000`), so `quote_match` is 1.0 for every XBRL fact; screener facts quote the row as printed; legacy facts quote the JSON field. Derived facts join their input quotes and take the lowest `quote_match`.
  - Screener fallback emits no `tax` (it only prints a whole-number Tax %) and, for banks, only `nii`, `other_income`, `pbt`, `pat` (its "Revenue" is interest earned and its "Financing Profit" is not PPOP).
  - Legacy `results-comparision` carries no basis. Its INFY Dec 2024 sales (Rs 34,915 cr) differ from screener's consolidated 41,764, so it is standalone; facts are labelled standalone and used only for a standalone company (test `test_legacy_is_standalone_not_consolidated`).
  - Periods: `FY27Q2`, `FY27H1`, `FY27H2`, `FY27-9M`, `FY27`. `H2` is added to `period_kind` (CLAUDE.md lists Q|H1|9M|FY but also asks for a derived H2); CLAUDE.md is unchanged, update its contract line if you agree. Q4 = FY - 9M is the fallback when a March filing has no quarter column (all real filings seen so far do carry one); H2 = FY - H1 is implemented and tested, not yet used. A string naming two dates, a month that is not a quarter end, or a bare "Q2 2026" raises `PeriodError`.
  - `Verdict.actual_fact_id` may be null for `went_quiet` as well as `not_enough_evidence` (a claim that went quiet has no fact to point at).
  - `quote_match` normalises with NFKC, lowercase, punctuation -> space; a quote under 4 words counts as one run.
  - `arithmetic_ok(pbt, tax, pat, exceptional=None, other=None)`: `exceptional` only when PBT is before exceptional items; `other` for associates/discontinued; missing input returns False.
  - XML is parsed with entity resolution and network access off. `supabase>=2.33` is pinned in pyproject (2.33.0 builds clients from `sb_publishable_`/`sb_secret_` keys, tested offline with dummy values); `web/` has no supabase-js yet, so nothing to upgrade there (latest on npm is 2.118.0).
  - `ScreenerCompany.page_text` and `ScreenerTable.row_text` were added (S1 module) so screener facts can carry a real quote and quote_match.
